# Уфологічна мапа — технічний план

Оновлено: 21.11.2026. Жива версія документа: https://claude.ai/artifact/8reNLuGKRoEQyDgwEyw1uy

## Огляд

Будуємо статичну вебмапу точок аномальної енергії за зразком DeepStateMap: темна карта, кольорові маркери й зони, бокова панель з деталями та повзунок часу. Перша версія — без бекенду: дані лежать у GitHub-репозиторії як GeoJSON, сайт збирається GitHub Actions і хоститься на GitHub Pages безкоштовно.

- **Хто наповнює:** на етапі 1 — лише автор проєкту; пізніше — уфологи, езотерики, очевидці через форму GitHub Issue з модерацією.
- **Хто дивиться:** будь-хто за посиланням `https://<user>.github.io/ufo-map/`.
- **Як розробляємо:** Claude Code у VS Code, етапами з готовими промптами (`docs/PROMPTS.md`).
- **Вартість MVP:** 0 грн — GitHub Pages, безкоштовні тайли карти, без серверів.

## Стек і архітектура

| Шар | Вибір | Чому |
| --- | --- | --- |
| Збірка | Vite + TypeScript | Швидкий dev-сервер, типи для моделі даних |
| UI | Vanilla TS (або Preact, якщо панелі ускладняться) | Малий бандл, менше залежностей |
| Карта | MapLibre GL JS | Вектор, вбудована кластеризація GeoJSON, фільтри на GPU |
| Підкладка | OpenFreeMap або CARTO Dark Matter | Безкоштовно; атрибуція OSM обов'язкова |
| Дані | GeoJSON-файли в `data/` | Редагуються в PR, історія змін у git |
| Валідація | JSON Schema + ajv | CI відхиляє зламані точки |
| Пошук | Fuse.js | Нечіткий пошук у браузері |
| Тести | Vitest + Playwright (smoke) | Логіка фільтрів і чи відкривається карта |
| CI/CD | GitHub Actions → GitHub Pages | Деплой на кожен push у `main` |

Потік даних: `data/points/*.geojson` → (`scripts/validate-data.ts`, `scripts/build-data.ts`) → `public/data/all.geojson` → браузер (MapLibre). Сервер і база даних для MVP не потрібні.

## Модель даних

Кожна точка — GeoJSON Feature (Point, LineString або Polygon) з фіксованим набором полів у `properties`. Схема — `schema/point.schema.json`.

```json
{
  "type": "Feature",
  "geometry": { "type": "Point", "coordinates": [27.978, 51.302] },
  "properties": {
    "id": "ua-zht-0001",
    "title": { "uk": "Кам'яне Село", "en": "Stone Village (Kamiane Selo)" },
    "description": { "uk": "…", "en": "…" },
    "category": "place_of_power",
    "observed_at": null,
    "added_at": "2026-11-21",
    "source_type": "esoteric",
    "sources": ["https://…"],
    "credibility": 1,
    "precision_m": 300,
    "reporter": "seed",
    "region": "Житомирська обл.",
    "tags": ["валуни", "легенди"],
    "media": [],
    "status": "published",
    "safety_note": "необов'язкове"
  }
}
```

| Поле | Значення |
| --- | --- |
| `category` | `ufo_sighting` (НЛО), `energy_anomaly`, `place_of_power`, `magnetic_anomaly`, `crop_circle`, `ley_line`, `paranormal`, `other` |
| `source_type` | `ufologist`, `esoteric`, `eyewitness`, `media`, `measurement` (є дані приладів) |
| `credibility` | 1 — чутки/легенда, 2 — один очевидець, 3 — кілька незалежних, 4 — є фото/відео, 5 — є вимірювання |
| `observed_at` | `YYYY`, `YYYY-MM` або `YYYY-MM-DD`; `null` для місць без дати |
| `precision_m` | Наскільки точна локація; ≥ 500 м — на карті коло невизначеності |
| `status` | `published`, `disputed` (спірна), `debunked` (пояснена — сірий маркер) |
| `safety_note` | Попередження (окупована / небезпечна територія) — червона плашка |

Стартові дані: `data/points/ua.geojson` (30 точок) і `data/points/nl.geojson` (15 точок), кожна з посиланням на джерело.

## Додавання точок

**Етап 1 (зараз):** форма для сторонніх людей вимкнена — точки додає лише автор, напряму в `data/points/` (або попросивши Claude Code). CI перевіряє схему.

**Пізніше:** нові точки надходять через GitHub Issue Form і потрапляють на карту тільки після лейбла `approved` від модератора:

1. Автор заповнює Issue Form.
2. Модератор перевіряє → «Схвалено?»
3. Так → GitHub Action створює PR → CI (схема, дублі) → Merge у `main` → деплой на Pages.
4. Ні → issue закривається з поясненням.

Поля форми `new-point.yml`: назва і категорія; координати `lat, lng` (кнопка на карті підставляє їх у URL форми); точність 50 м / 500 м / 5 км; дата спостереження, опис, тип джерела; посилання на джерела та фото (лише власні або з дозволом); чекбокс «Точка не є приватним житлом і не розкриває персональних даних».

## Деплой і CI

Кожен push у `main` збирає сайт і викладає його на GitHub Pages за 1–2 хвилини. У налаштуваннях репозиторію: **Settings → Pages → Source: GitHub Actions**.

| Workflow | Коли запускається | Що робить |
| --- | --- | --- |
| `validate.yml` | Кожен PR | `npm ci` → `validate` → `vitest` → `vite build` |
| `deploy.yml` | Push у `main` | Збірка → `actions/upload-pages-artifact` → `actions/deploy-pages` |
| `issue-to-pr.yml` | Лейбл `approved` на issue (пізніше) | `issue-to-point.ts` → гілка `point/<id>` → PR |

Нюанси GitHub Pages:
- У `vite.config.ts` потрібно `base: '/ufo-map/'`, інакше скрипти й дані не завантажаться.
- Маршрути через `#hash`, бо Pages не підтримує SPA-rewrite.
- Репозиторій має бути публічним (на безкоштовному плані Pages працює лише для публічних).
- Для `issue-to-pr.yml` увімкніть **Settings → Actions → Allow GitHub Actions to create pull requests**.
- Власний домен пізніше: файл `public/CNAME` + DNS-запис.

## Ризики і правила

| Ризик | Захист |
| --- | --- |
| Точка вказує на приватне житло чи людину | Заборона в правилах; для житлових зон координати округлюються до ≥ 500 м; без імен очевидців |
| Військові чи критичні об'єкти | Чинні об'єкти не публікуються; історичні кейси — з узагальненням координат до кількох км |
| Покинуті чи небезпечні місця, окупована територія | Поле `safety_note`, червона плашка в картці |
| Чужі фото й тексти | Лише власні або з ліцензією; інакше — посилання на джерело |
| Спам і фейки | Ручна модерація, шкала `credibility`, статуси `disputed` / `debunked` замість видалення |
| Ліміти тайл-сервера | Два провайдери в конфігу, перемикання одним рядком |
| Великий all.geojson (тисячі точок) | На етапі 2 — векторні тайли PMTiles у тому ж репозиторії |

Дисклеймер для сайту:

> Карта збирає повідомлення уфологів, езотериків і очевидців. Вони не є науково підтвердженими фактами. Не відвідуйте приватні, закриті чи небезпечні території.

## Дорожня карта

Бекенд потрібен лише на етапі 3.

1. **Етап 1 · MVP** — статичний сайт на GitHub Pages; карта, фільтри, повзунок часу; дані в GeoJSON у репозиторії. *Перехід далі:* 20+ реальних точок і робоча форма.
2. **Етап 2 · Масштаб** — теплова карта, PMTiles для тисяч точок, шар небезпечних зон, власний домен. *Перехід далі:* 500+ точок або потреба в акаунтах.
3. **Етап 3 · Спільнота** — Supabase + PostGIS, акаунти й коментарі, голосування «підтверджую», PWA для польових виходів. Фронтенд лише міняє джерело даних з all.geojson на API Supabase.
